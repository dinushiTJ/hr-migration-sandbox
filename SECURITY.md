# Security and Data Handling

## Publication rule

Do not commit real HR, payroll, or other personal data. The files generated by
`src/generate_sources.py` are synthetic demonstration data and are intentionally
ignored by Git. Treat any supplied extracts as confidential until the data owner
has approved their use and disclosure.

Before publishing a generated artefact, confirm that it contains no real
identifiers, names, salaries, manager relationships, or raw source records.
The SQLite database, JSON export, and HTML replay are deliberately ignored
because they retain source and quarantine records.

## Safe operating practices

- Run the pipeline with least-privilege filesystem access and review inputs before loading.
- Keep `data/` and `out/` outside public hosting and avoid uploading them to issue trackers.
- Use approved secret storage; never put credentials, tokens, or connection strings in this repository.
- Review generated diffs and scan commits for personal data before pushing.
- Keep dependencies and the Python runtime patched when adapting this sandbox for production.
- Treat validation and reconciliation as release gates, not as proof that disclosure is safe.

## Reporting

Do not report suspected personal-data exposure in a public issue. Contact the
repository owner privately with the affected path, commit, and a minimal
reproduction. Do not attach the exposed data.
